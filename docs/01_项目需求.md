# 01 项目需求

## 1. 项目信息

| 项 | 内容 |
|---|---|
| 项目名称 | 基于 Web 的智能巡检机器人二维仿真系统 |
| 小组名称 | 智能巡检仿真小组 |
| 仓库地址 | https://github.com/ruisen77-gif/patrol-sim-std |
| 计划完成的版本 | 基础版 + 标准版 + 进阶版七项拓展 |
| 技术形态 | 纯软件仿真，无实体硬件、无 GPU、无付费大模型 API |

## 2. 拟实现的功能范围

### 2.1 基础版（必须全部通过）

| 需求 | 验收方式 | 本项目实现 |
|---|---|---|
| Web 界面与二维地图 | 能看到地图、区分机器人与障碍物 | 20×20 Canvas 网格，障碍物深色红边，机器人蓝色发光块并显示朝向 |
| 后端 API | 能取地图与状态，能下发控制指令 | Flask 六个接口，见 `docs/03` |
| 手动控制 | 按指令移动，越界保持在图内 | 嵌入式模块先判边界与障碍，失败返回 409 与原因 |
| 状态反馈 | 页面显示与 API 一致 | 前端每 1 秒轮询 `/api/robot` 与 `/api/sensor` |
| Git 版本管理 | 仓库可访问、可查提交记录 | 五人同一仓库，任务分支 + PR 合并 |
| 基础 CI | 仓库自动跑至少一项检查 | GitHub Actions 跑 `compileall` 与 `pytest` |
| Docker 部署 | 按文档能起页面并手动控制一次 | 根目录 `Dockerfile` + `docker-compose.yml`，一条命令启动 |

### 2.2 标准版（四项全部实现）

| 需求 | 验收方式 | 本项目实现 |
|---|---|---|
| 自动巡检 | 按 P1→P2→P3 顺序到达，页面显示完成状态 | 算法串联路径，机器人逐点行进，前端显示进度 |
| 路径规划 | 绕障生成可通行路径，不可达有反馈 | BFS 网格寻路，无解返回 `ok=false` 与说明 |
| 虚拟传感器 | 至少一种感知，随位置变化 | 前 / 左 / 右三格探测 + 碰撞 + 越界，随位置实时变化 |
| 简单异常处理 | 显示原因并停止相关操作，状态仍可查看 | 撞障 / 越界 / 不可达三类告警弹窗，任务暂停，状态接口仍可读 |

### 2.3 进阶版拓展（七项）

| 拓展功能 | 解决的问题 | 验证方式 |
|---|---|---|
| 科技 HUD 控制台界面 | 原页面像作业，演示时不易讲清系统结构 | 深色底、发光网格、状态指示灯、三区布局 |
| 路径轨迹可视化 | 看不出规划结果与执行进度 | 待走路径青色虚线、已走过路径浅蓝实线 |
| P1/P2/P3 巡检点标记 | 不知道机器人在巡哪些点 | 地图标注序号，当前目标点高亮 |
| 仿真速度调节 | 全速跑完看不清过程 | 滑块切换 0.5x / 1x / 2x / 4x |
| 告警弹窗 | 异常只在角落显示文字，容易被忽略 | 碰撞、越界、不可达触发半透明弹窗，可关闭 |
| 点击地图设置巡检点 | 巡检点写死，无法现场演示 | 点击空格即新增点位，启动巡检按新点位执行 |
| 巡检任务进度 | 不知道还剩多少 | 底部显示已完成 / 总点位、剩余步数 |

## 3. 明确不做的内容

- 日志面板（策划书明确不要求）。
- 真实机器人硬件接入、真实摄像头或激光雷达。
- WebSocket 实时推送、数据库、用户登录与权限。
- 任何付费大模型 API 调用。
