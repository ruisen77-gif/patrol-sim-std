# 项目需求

学员从零开发一个基于 Web 的智能巡检机器人二维仿真系统。用户打开页面后，可以查看地图，发出移动指令，并看到机器人的位置、朝向和运行状态。完成基础版后，可继续实现自动巡检。

项目可个人完成，也可由 2–5 人组队完成。技术方案自行选择，普通电脑即可运行。计划完成的版本为 `标准版`，拟实现的功能范围为 `基础版全部 7 项 + 标准版全部 4 项 + 进阶版 7 项拓展`。

本项目由小组 `求也得排队` 完成，成员为江睿森、张文良、李凯迪、王如彬、蔡健楠，分工见[小组分工](02_小组分工.md)。技术实现是原生 HTML/CSS/JavaScript 单页前端 + Python Flask 后端，三个仿真模块（机器人运动、BFS 寻路、虚拟传感器）位于 `backend/sim/`，接口与字段口径见[项目架构与接口](03_项目架构与接口.md)。

## 基础版（最低目标）

| 需求               | 验收方式                                                                                                                                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web 界面与二维地图 | 打开 `http://127.0.0.1:5050`，能看到 20×20 二维地图，机器人（蓝色发光方块 + 朝向指针）与障碍物（深红描边格）可区分，地图边界清晰。                                             |
| 后端 API           | 按[接口说明](03_项目架构与接口.md)请求 `/api/map`、`/api/robot`、`/api/sensor` 能获取地图与机器人状态；`/api/move` 能下发手动控制指令并返回执行结果。                          |
| 手动控制           | 在 Web 页面点方向键或按键盘方向键，机器人逐格移动；朝地图边界移动时被拦截并提示原因，机器人保持在 0–19 范围内。                                                               |
| 状态反馈           | 操作后页面坐标卡、运动状态、朝向指针随之更新；页面数据来自每 1 秒轮询的 `/api/robot` 与 `/api/sensor`，与接口返回一致。                                                       |
| Git 版本管理       | 提交可访问的项目仓库地址 <https://github.com/ruisen77-gif/patrol-sim-std.git>，能查看源码和开发过程中的提交记录。见[Git 协作与验收](#git-协作与验收)。                        |
| 基础 CI            | 仓库能自动运行至少一项与项目相关的检查。当前仓库已包含 `backend/test/test_sim.py`（BFS 不可达、撞障拦截两例），`.github/workflows/ci.yml` 尚未入库，由运维补充后可查看运行结果。 |
| Docker 部署        | 按[运行与结业提交](04_运行与结业提交.md)执行 Docker 部署步骤，能打开页面并完成一次手动控制。现有 `Dockerfile`、`docker-compose.yml` 的构建路径与端口需与 `app.py` 的 `PORT` 默认值对齐后再验证。 |

## 标准版（推荐目标）

完成基础版后，可以按所选专项方向增加功能。个人或人数较少的小组完成所选方向的任务即可。组队时，每位成员按分工完成自己负责的任务。下表为可选功能及各自的验收方式，验收时按实际选定的任务核对。

| 需求         | 验收方式                                                                                                                                                       |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 自动巡检     | 在地图上点选 P1、P2 后点「启动自动巡检」，机器人按顺序到达各巡检点；页面显示「已完成 / 总点位」与剩余步数，全部到达后状态显示「已完成」。                        |
| 路径规划     | 自动巡检时生成绕过障碍物的可通行路径（`path_planner.bfs` + 多点串联）；目标点被障碍物包围时接口返回 409「目标点不可达」，部分点位不可达时跳过并在 `unreachable` 中列出。 |
| 虚拟传感器   | `/api/sensor` 返回前 / 左 / 右三向受阻、碰撞、越界五项读数；移动机器人或改变朝向后，障碍物方向读数随之变化，页面传感器状态卡同步更新。                            |
| 简单异常处理 | 撞障碍、越界、巡检点不可达三类场景分别弹出告警并写明原因，相关移动或任务被阻止；任何时刻 `/api/robot`、`/api/sensor` 仍可查看机器人状态。                       |

本项目四项全部实现，分工为：全栈负责接口编排与前端交互，算法负责 BFS 与多点串联，人工智能负责虚拟传感器，嵌入式负责机器人运动与边界判断。

## 进阶版（自由拓展）

可按兴趣选择 AI 模型、Agent、更复杂的路径规划算法、机器人控制或其他工程化功能。进阶功能均为选做。选择拓展后，填写功能、解决的问题和验证方式。

本项目选择的七项拓展如下：

| 功能                 | 解决的问题                                 | 验证方式                                                                                       |
| -------------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| 科技 HUD 控制台界面  | 原页面像作业，演示时讲不清系统结构         | 深色底、发光网格、HUD 角线与状态指示灯；左侧控制区、中间地图区、底部状态卡三区布局可辨。        |
| 路径轨迹可视化       | 看不出规划结果与执行进度                   | 启动巡检后地图上出现青色待走虚线（带圆点）与浅蓝已走实线，随机器人行进实时变化。                |
| 巡检点标记 P1/P2/P3  | 不知道机器人在巡哪些点                     | 巡检点在地图上标注 P1、P2…序号，当前目标点显示为黄色高亮。                                      |
| 仿真速度调节         | 演示时全速跑完看不清过程                   | 滑块切换 0.5x / 1x / 2x / 4x，机器人每格间隔分别约为 0.8 / 0.4 / 0.2 / 0.1 秒，差别肉眼可见。   |
| 告警弹窗             | 异常只在角落显示文字，容易被忽略           | 碰撞、越界、不可达三类场景弹出半透明告警并写明原因，4.2 秒后自动消失，也可点 ✕ 关闭。           |
| 点击地图设置巡检点   | 巡检点写死，无法现场演示                   | 点击空格新增巡检点并自动编号，再点同一格移除；障碍格拒绝并提示；数量上限 6 个。                  |
| 巡检任务进度         | 不知道还剩多少                             | 底部状态卡显示「已完成 / 总点位」与剩余步数，进度条按完成比例伸缩，每到达一个点即更新。          |

全栈、运维、算法、人工智能、嵌入式与具身智能等方向可作为选题和分工参考。本项目**不实现**日志面板（策划书要求）、用户系统与数据持久化，也不使用 WebSocket，状态一律轮询。

## Git 协作与验收

1. **使用自己的项目仓库。** 从模板创建个人或小组仓库后，首次推送前用 `git remote -v` 确认 `origin` 指向自己的项目仓库。小组成员在同一个项目仓库协作，PR 也以该项目仓库的分支为合并目标。
2. **按任务保存进度。** 完成一项功能、修复或文档更新后，检查差异并单独提交。标题写清具体改动，建议使用 `feat`、`fix`、`docs` 等前缀。验收时可以从提交记录看出项目的开发过程，提交次数由实际工作决定。
3. **按项目规模选择分支流程。** 个人项目可以直接向默认分支提交。小组项目建议先同步默认分支，再创建 `feat/manual-control` 这类短期任务分支。完成检查后用 PR 合并，在 PR 里写明改动、实际执行的检查和结果。遇到冲突时与相关成员核对后再合并。
4. **提交前检查文件和结果。** 确认提交只包含本次任务相关的文件，排除密码、令牌、本地依赖目录和可重新生成的构建产物。交付时确认验收人员能查看仓库、提交历史和基础 CI 的实际运行结果。小组成员的工作内容可结合[小组分工](02_小组分工.md)核对。

提交标题示例

```text
feat(frontend): 显示机器人当前位置
feat(backend): 新增巡检启动接口与路径下发
fix(backend): 阻止机器人移出地图边界
docs: 按当前实现重写 03 架构与接口文档
docs: 补充 Docker 部署步骤
```
