# 前端说明

## 页面功能

- 20×20 Canvas 地图，障碍物、机器人、巡检点、路径与轨迹实时绘制
- 机器人绘制为俯视小车（车头指向当前朝向），行进时车顶示警灯红蓝交替、轮胎辐条转动、车头光束呼吸；手动单步移动成功后另有一次约 240ms 的短闪反馈（车身转青、示警灯快闪）。动效由 `index.html` 顶部 `FX` 常量统一开关，改 `false` 即回到纯静态小车
- 数据轮询自适应：静止 1 秒一次，行进中 250 毫秒一次；行进中车身位置按采样间隔做线性插值（`displayPos()`），避免每秒瞬移 2–3 格的割裂感，视觉滞后约半格以内
- 左侧控制区：方向键、启动 / 停止巡检、清空巡检点、复位机器人、速度滑块（巡检中拖动会调 `POST /api/speed` 实时改速）
- 点击画布添加或移除巡检点（最多 6 个），点位按「目标黄 / 已计入绿 / 乱序到访橙 / 未到访青」四色区分
- 底部五张状态卡：坐标、运动状态、传感器状态、告警、巡检进度（进度由后端 `progress` 下发；自动模式显示剩余步数，手动模式显示「手动巡检 · 按顺序」，乱序到点不计进度并弹一次提示，需重新按顺序走到才计数）
- 碰撞、越界、不可达三类告警弹窗；巡检进行中点方向键提示「请先点击『停止任务』再手动控制」

## 文件结构

| 文件 | 职责 |
|---|---|
| `index.html` | 页面骨架（约 100 行），只保留结构，不再内联样式与脚本 |
| `style.css` | 全部页面样式（HUD 配色、卡片、按钮、告警浮层） |
| `app.js` | 全部页面逻辑（Canvas 绘制、小车动效、交互、轮询、接口调用） |
| `test/smoke.mjs` | 冒烟测试：资源引用是否完整、`app.js` 语法是否可编译、关键逻辑是否还在 |

## 依赖

无第三方依赖，不需要构建。三个文件由 Flask 的 `static_folder` 直接托管，改完刷新即可。

## 后端地址配置位置

接口请求统一走同源相对路径，入口在 `app.js` 的 `api()` 函数：

```js
function api(path, options) {
  // fetch(path, ...) —— path 形如 "/api/robot"
}
```

页面由 Flask 托管时与后端同源，无需配置地址。若前端单独用静态服务器打开，把 `api()` 内的 `path` 拼上后端地址即可，例如 `http://localhost:5050` + path；同时后端已开启 CORS。

## 启动与联调验证

1. 启动后端：`python backend/app.py`
2. 打开 <http://localhost:5050>
3. 验证手动链路：点方向键 → 坐标卡变化；撞墙 → 弹出碰撞告警且坐标不变
4. 验证巡检链路：点击地图设置 P1、P2 → 点「启动自动巡检」→ 路径出现 → 进度更新 → 状态显示「已完成」

## 测试

```bash
node frontend/test/smoke.mjs   # 仓库根目录执行，无需安装依赖
```

覆盖：`index.html` 是否正确引用 `style.css` / `app.js`（并确认已无内联样式与脚本）、`app.js` 能否被编译、关键逻辑（实时改速、复位、点位同步、乱序提示、位置插值、`FX` 动效开关）是否还在。改完前端先跑一遍再提交。
